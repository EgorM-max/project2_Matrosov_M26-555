# Primitive DB

Primitive DB — консольное приложение на Python, имитирующее базовые операции управления таблицами базы данных.

Проект разработан на Python 3.12 с использованием менеджера пакетов `uv`.

## Возможности

- Создание таблиц с помощью команды `create_table`.
- Удаление таблиц с помощью команды `drop_table`.
- Просмотр списка таблиц через `list_tables`.
- Проверка типов данных столбцов: `int`, `str`, `bool`.
- Автоматическое добавление столбца `ID:int`.
- Сохранение структуры таблиц в JSON-файл `db_meta.json`.
- Загрузка сохранённых таблиц при повторном запуске.

## Команды приложения

| Команда | Описание |
|---|---|
| `create_table users name:str age:int active:bool` | Создать таблицу |
| `drop_table users` | Удалить таблицу вместе с записями |
| `list_tables` | Показать существующие таблицы |
| `info users` | Показать структуру таблицы и количество записей |
| `insert into users values ("Alex", 30, true)` | Добавить запись |
| `select from users` | Показать все записи |
| `select from users where age = 30` | Найти записи по условию |
| `update users set age = 31 where ID = 1` | Изменить записи |
| `delete from users where ID = 1` | Удалить записи по условию |
| `help` | Показать справку |
| `exit` | Завершить программу |

## Работа с данными

Приложение поддерживает три типа данных: `int`, `str`, `bool`.

При создании таблицы автоматически добавляется системный столбец `ID:int`. При добавлении записи идентификатор формируется автоматически.

Структура таблиц хранится в `db_meta.json`, а записи каждой таблицы сохраняются в отдельных JSON-файлах в папке `data/`.

Приложение поддерживает основные CRUD-операции: создание, чтение, изменение и удаление записей.

Для команд `select`, `update` и `delete` поддерживаются простые условия `where` с оператором `=`.

Данные сохраняются между запусками программы.

## Пример работы с базой данных

```text
create_table users name:str age:int active:bool
insert into users values ("Alex", 30, true)
insert into users values ("Maria", 25, false)

select from users
select from users where age = 30

update users set age = 31 where ID = 1
delete from users where ID = 2

info users
drop_table users
exit
```

## Декораторы и замыкания

В проекте реализованы декораторы и замыкания для улучшения работы базы данных.

### Обработка ошибок

Декоратор `handle_db_errors` перехватывает исключения, возникающие при выполнении операций базы данных.

Он обрабатывает `FileNotFoundError`, `KeyError`, `ValueError` и другие исключения, выводя понятные сообщения вместо аварийного завершения соответствующей операции.

### Подтверждение удаления

Декоратор `confirm_action` запрашивает подтверждение пользователя перед удалением таблиц и записей.

Пример:

```text
Введите команду: drop_table users
Вы уверены, что хотите выполнить "удаление таблицы"? [y/n]: n
Операция отменена.
```

При ответе `y` операция выполняется, при любом другом ответе отменяется.

### Измерение времени выполнения

Декоратор `log_time` измеряет время выполнения функций `insert` и `select` с помощью `time.monotonic()`.

Пример:

```text
Функция select выполнялась за 0.00001 секунд
```

### Кеширование запросов

Замыкание `create_cacher` создаёт кеш для результатов запросов `select`.

При первом выполнении запроса результат сохраняется в памяти. Повторный запрос к тем же данным и с тем же условием использует кешированный результат.

Пример:

```text
Введите команду: select from users
Результат сохранён в кеш.

Введите команду: select from users
Результат получен из кеша.
```

После успешных операций изменения данных (`insert`, `update`, `delete`, `create_table`, `drop_table`) кеш очищается.

Кеш хранится в оперативной памяти и не сохраняется между запусками программы.

## Проверка качества и сборка

Проект использует `uv` для управления зависимостями и запуска приложения, а также Ruff для проверки качества кода.
